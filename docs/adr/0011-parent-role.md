# ADR-0011: Parents link to students with a private invite code

Date: 2026-10-25
Updated: 2026-10-26

## Decision
- Add `PARENT` to the `role` enum. Parents sign up at `/api/onboarding/parent`
  (or the web register form) with name, email, password, and optional phone.
- Every user row gets a random `parent_invite_code` (e.g. `PB641BB3`). Students
  see their code on the profile page and share it with a parent.
- `POST /api/parent/link` attaches a parent to the student with that code.
  Links are many-to-many and idempotent (`parent_students` unique pair).
- Parents get read-only views: `GET /api/parent/students` (children, groups,
  progress) and `GET /api/parent/students/:studentId/groups/:groupId/grades`.
  They cannot call student write endpoints (quiz submit, lesson complete, join).

## Rationale
- Phone/email matching would let anyone who knows a student's number read their
  grades. A code is a small secret the student controls.
- A separate link table keeps one parent able to follow siblings and one student
  able to have two parents, without changing the `user` table further.
- Reusing `StudentService.myGroups` / `myGrades` after an ownership check keeps
  parent and student numbers identical by construction.

## Consequences
- The code is visible in `GET /api/me`; treat it like a password. Students can
  rotate it with `POST /api/student/parent-code/rotate`, which deletes every
  `parent_students` row for that student and issues a new code in one
  transaction. The web profile exposes the code and rotation; the mobile
  profile does not yet.
- Codes are generated by a Postgres default expression, so new rows and
  backfilled rows get one without app code. Collisions fail the unique
  constraint instead of silently sharing access.
- Parent UI exists on web and mobile: link/unlink children, see groups and
  progress, and open quiz/manual grades. Parents remain read-only and cannot
  call student write endpoints or read lessons/attachments.
- Enrollment and move notices go to the linked parent's in-app inbox. The
  monthly summary additionally uses email and WhatsApp when configured.
